# `openshift/` — full deployment set

Everything needed to bring up gbaia (NAIA) + ND-MCP + Intersight-MCP on a fresh
OpenShift 4 cluster, with one command after filling in `.env`.

## Layout

Numeric prefixes set apply-order for `oc apply -R -f openshift/`.

```
openshift/
├── 30-neo4j/                    knowledge graph (PVCs + Deployment + Service)
├── 40-nd-mcp-postgres/          ND-MCP state store
├── 50-nd-mcp-server/            ND-MCP server (BC, IS, Deploy, Svc, Route)
├── 55-nd-mcp-webui/             optional admin UI (BC + IS + Svc; build currently fails — not critical)
├── 60-intersight-mcp/           Intersight MCP server
├── 70-ingestor/                 APIC/ND/Intersight → Neo4j ingestor (BC + IS + Deploy)
├── 80-backend/                  FastAPI app (BC + IS + Deploy + Svc + Route + config PVC)
├── 90-frontend/                 Gradio UI  (BC + IS + Deploy + Svc + Route)
├── deploy.sh                    one-shot bring-up: ns, secrets, manifests, builds
├── .env.example                 → copy to .env, fill in, then run deploy.sh
└── README.md                    (this file)
```

Each Deployment carries an `image.openshift.io/triggers` annotation, so the
container image fields use bare `<is-name>:latest` and OpenShift's image
controller rewrites them to the cluster-local registry path automatically.
That makes the manifests namespace- and cluster-portable.

## One-shot deploy

```bash
cp openshift/.env.example openshift/.env
# edit openshift/.env — set namespace, APIC + ND creds, optional LLM endpoint, etc.
# if you want Intersight ingestion, save the PEM private key locally and point
# INTERSIGHT_PRIVATE_KEY_FILE at it.

cd openshift
./deploy.sh
```

`deploy.sh` is idempotent — safe to re-run after editing `.env`.

## Three secrets created by `deploy.sh`

The manifests reference these by name; values stay out of git.

| Secret | Consumers | Keys |
|---|---|---|
| `gbaia-secrets` | backend, ingestor | `apic-url/user/password`, `nd-url/user/password`, `neo4j-password`, `openai-api-key`, `local-llm-token`, `ai-defense-api-key`, `model-proxy-api-key`, `splunk-access-token` |
| `gbaia-nd-mcp-secrets` | nd-mcp-server, nd-mcp-postgres, backend | `POSTGRES_*`, `DATABASE_URL`, `MCP_API_TOKEN`, `ENCRYPTION_KEY` (Fernet), `ND_URL/USER/PASSWORD` |
| `gbaia-intersight-secrets` | intersight-mcp, ingestor | `api-key-id`, `private-key` (PEM file), `base-url` (no `/api/v1`, for Python SDK), `base-url-mcp` (with `/api/v1`, for the TS MCP) |

> The `base-url` / `base-url-mcp` split is mandatory — the Python SDK
> auto-prepends `/api/v1` to every path, while the TS MCP does not. See the
> code comments in `ingestor/ingest_nw_data.py` and earlier session notes.

## Cluster-specific knobs to verify before first deploy

These default to the values that work on the `runai-south` ns of the
`ocpai-02` cluster. Change in `.env` before running `deploy.sh`:

| `.env` var | Where it lands | Why it varies per cluster |
|---|---|---|
| `LOCAL_LLM_URL` | backend → `LOCAL_LLM_URL` env | URL of your in-cluster vLLM. Leave empty to fall back to OpenAI. |
| `LOCAL_LLM_MODEL` | backend → `LOCAL_LLM_MODEL` env | Model name your vLLM exposes (e.g. `qwen3.6-27b`, `mistral-nemo-12b`). |
| `BACKEND_EXTERNAL_URL` | frontend → `BACKEND_EXTERNAL_URL` env | The browser-facing route to the backend. Auto-generated by OpenShift unless you customize the Route's `host`. After first apply: `oc get route gbaia-backend` and copy back into `.env`. |
| `INTERSIGHT_REGION_HOST` | both Intersight secrets | `intersight.com` (US), `eu-central-1.intersight.com` (EU), etc. |
| `*_GIT_URI` | BC `spec.source.git.uri` | If you forked any of the source repos, point the BC at your fork. |

## Single-deploy verification

After `deploy.sh` finishes and the builds complete:

```bash
oc -n $NAMESPACE get deploy        # everything 1/1 (backend 2/2)
oc -n $NAMESPACE get route         # find the gbaia-frontend hostname
oc -n $NAMESPACE exec deploy/gbaia-backend -- python3 -c "
import urllib.request, json
d = json.loads(urllib.request.urlopen('http://localhost:8000/api/capabilities').read())
for k,v in d['data_sources'].items(): print(f'  {k}: available={v.get(\"available\")}')
"
```

You should see APIC, Nexus Dashboard, and Intersight all `available=True` once
the first ingestor cycle completes (~30s after the ingestor pod is ready).

## Removing nd-mcp-webui (optional)

The webui build currently fails (multi-stage Dockerfile + strict short-name
mode in OpenShift CRI-O — not worth fixing for what is just an admin UI).
Either skip the dir or `oc -n $NAMESPACE delete -f openshift/55-nd-mcp-webui/`.

## What's intentionally NOT included here

- **ImageStream `vlab-llm-secret` references** — old manifests had the backend
  reading the LLM bearer token from `vlab-llm-secret` (a per-cluster secret).
  Now read from `gbaia-secrets.local-llm-token` instead, so the deploy stays
  self-contained.
- **HPA / ScaledObject** — none were in use on the source cluster; add later
  if needed (fp-ocp had a KEDA-based one against ThanosQuerier).
- **Network Policies** — Cilium policies are out of scope for this bundle. See
  `project_cilium_zero_trust_analysis.md` in the memory index.
